// 02. approach

The interesting
problems are
always specific.

Not "build a CRUD app" — but "cut 3 hours of gaming footage to 90 seconds automatically, reliably, overnight." The specificity is where the real engineering happens. Generic tools are built once and forgotten. Specific ones get used every day.

The goal for any system is that it runs a month later without anyone touching it. Clean code, clear logic, no workarounds that need a comment to explain. If a future reader needs to ask why, the code hasn't done its job.
